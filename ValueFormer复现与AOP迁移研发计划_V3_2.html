ValueFormer 复现与 AOP / Lite-LDA 迁移研发计划 V3.2

基础论文：arXiv:2608.02958 v1 关联项目：State Critic / AOP / Contact AOP / Lite-LDA 版本：V3.2 · 2026-08

一句话定位

V3.2 将研发工作严格拆成两条互不混淆的主线：Paper Reproduction Track 用于忠实复现 ValueFormer 的 State Critic V(s)、原始 stage-aware 标签与 BCE 训练设置；Industrial Track 用于精密插入任务，采用独立的 Task Phase / Physical Progress / Contact State 三套标签，并逐步升级到固定时域 Q_H(s,a) 的 Action Outcome Predictor、Force/Tactile Contact AOP，最后仅在真实动作排序已经成立后进入 physical-grounded Lite-LDA。V3.2 的核心原则是：论文复现回答“能否复现”，工业标签回答“是否真正适合毫米级接触”，二者不得用同一套标签强行统一。

V3.2 相对 V3.1 的修订记录

证据闭环1.1 节补充 ValueFormer v1 Section IV-E、Eq. (6)–(7) 的可追溯来源：V_mc 为 soft-target BCE，V_bin 为 weighted BCE，β=1.0；validation MSE 仅用于评估/early stopping，不再存在“待核实”状态。
核心新增新增“Paper Label Track / Industrial Label Track”双轨 Label Engine。工业 Physical Progress 不再由阶段序号或 episode 时间比例生成。
核心新增给出可实现的 Industrial Physical Progress 生成函数：对 approach、alignment、insertion depth、contact quality、jam/slip/overload 等物理量归一化后形成可回退的连续 potential，并规定终态 override、平滑与版本化策略。
修复Task Phase S0–S6、Physical Progress、Contact State 完全独立保存；Phase 只描述“当前在做什么”，不再直接决定 progress 数值。
新增新增 Phase 3B Cross-policy Generalization，单独分配 0.5–1 周，并设置相对性能下降 Gate，避免“随后再测”停留在附注层面。
修复阶段4时长正式记录为 2–3 周，原因是新增 Canonical Action、Candidate Generator、Sim→Real calibration 与真实 paired ranking。
修复修正 V3.1 中“相对 V3.1 / 在 V3.1 基础上”等版本文字错误，并删除“并行验证哪种训练目标才是论文设置”的旧措辞。
工程新增Candidate Action 在进入 AOP 前增加 deterministic safety envelope；真实 paired action 明确采用可重复 reset / matched initial conditions，是近似反事实而非数学意义上的同状态双执行。

01事实基线、证据与概念边界

1.1 ValueFormer 论文训练目标：已核实并可追溯

论文事实ValueFormer v1 的 Section IV-E “Training Objective” 明确联合训练两个 head。连续价值头 V_mc 使用 soft-target binary cross-entropy；二值异常头 V_bin 使用带类别平衡的 weighted BCE；总损失中的二值头权重 β=1.0。论文同时明确说明 validation MSE 是 measurement，而不是训练信号。

Paper reproduction baseline

L = L_mc + β · L_bin
L_mc  = BCE(logit_mc, soft_target v ∈ [0,1])        # Eq. (6)
L_bin = weighted_BCE(logit_bin, binary_target)       # Eq. (7)
β = 1.0

Optimization / selection notes from paper:
- training objective: BCE
- validation MSE: evaluation + checkpoint / early-stopping signal
- γ = 0.99 for MC labels

论文追溯信息

来源：ValueFormer: A Causal Transformer Value Function with Stage-Aware Labels for Semi-Autonomous Vision-Language-Action Policies, arXiv:2608.02958 v1，Section IV-E，Eq. (6)–(7)。建议研发仓库 README 固定记录论文版本号，防止后续 arXiv revision 改动导致“复现配置漂移”。

1.3 ValueFormer、AOP 与 Lite-LDA 的边界

State Critic / ValueFormer
Observation history ───────────────────────→ V(s)
回答：当前状态是否健康、是否在推进？

Action Outcome Predictor / AOP
Observation history + canonical action ───→ Q_H(s,a)
回答：未来 H 时间内，这个动作会造成什么短期结果？

Lite-LDA / Physical-grounded World Critic
latent state + action ─────────────────────→ z_future + physical future
回答：动作将如何改变未来 latent / geometry / contact / progress？

工程定义AOP V0 不应只输出一个难解释的 scalar Q。首版采用可解释 multi-head short-horizon outcomes，再由它们形成排序分数：

Recommended AOP heads
ΔProgress
P(Jam | H)
P(Slip | H)
P(Success within H)
ΔEE-target pose
ΔInsertion depth
Contact transition

Example ranking score
Score = w1·ΔProgress - w2·P(Jam) - w3·P(Slip) + w4·P(Success_H)

首版 H 建议从 0.25–1.0 s 试验；它是任务配置，不是固定论文参数。所有 candidate action 的 duration / sampling frequency 必须归一化后才进入 AOP。

1.4 多速率系统边界

State Critic / AOP 不能承担高速安全控制。建议把不同任务放在其适合的时间尺度：

VLA / Policy                  2–10 Hz
State / World Critic          5–20 Hz
AOP reranking                 5–20 Hz（按事件可提高）
Contact Critic               20–100 Hz
Force/Tactile residual       50–500+ Hz
Joint / impedance control   500–1000 Hz
硬边界：jam / overload / collision 的硬安全退出不依赖 ValueFormer/AOP 学习输出；机器学习只能提供附加预测，不能替代控制器和独立安全阈值。

02双轨 Label Engine：V3.2 的核心改动

2.1 为什么必须双轨

ValueFormer 原任务是六个有序语义 stage 的三明治装配，stage-aware success-then-decay 的主要目标是避免失败 episode 的正常前缀被错误标成 0。精密插入任务则存在 S4→S2→S3→S4 的回退、jam 后撤、重新搜索等真实非单调过程。因此 V3.2 明确：

Label Engine
│
├── Track A · Paper Reproduction Labels
│     目的：验证 ValueFormer 方法是否忠实复现
│     公式：严格按论文 stage-aware MC label
│
└── Track B · Industrial Physical Labels
      目的：训练真正适用于精密接触的 Critic / AOP
      字段：Task Phase + Physical Progress + Contact State + Mistake
禁止事项不得为了“保持与论文一致”而让 Track B 继续用 stage index / total stages 作为最终 progress；也不得用 Track B 的工业标签结果反过来宣称“论文复现成功”。

2.2 Track A：Paper Reproduction Label

论文事实Paper Track 只用于复现。成功 episode 沿 discounted MC curve；失败 episode 在估计失败阶段之前保留与成功相同的前缀，之后再衰减。核心参数按论文版本固定，例如 γ=0.99。

Eq. (2) — Success episode
v_k^succ = γ^(N-1-k)

Eq. (3) — Failed episode
s_fail = number of fully completed ordered stages before failure
k_fail = floor((s_fail / N_s) · N)

v_k^fail = γ^(N-1-k)                         , k ≤ k_fail
           v_k_fail · γ^(k-k_fail)           , k > k_fail

Eq. (4) — Sharp mistake target
v_bin(k) = 0  if sample k falls inside any annotated mistake interval
           1  otherwise

注意：以上仅属于 Paper Track。
不要把工业版非单调 progress 逻辑塞进该复现分支。

Track A 至少保留论文中的 flat-zero / cliff / late-diverge 等 label-shape ablation，用来确认“标签形状比架构更重要”的论文结论能否在自有数据上部分重现。

2.3 Track B：Task Phase —— 只描述“当前在做什么”

Phase定义主要观测允许回退
S0Free-space approachtip-target distance / EE pose是
S1Pre-contact alignment横向误差 / 角度误差是
S2First / renewed contactFz / tactile onset是
S3Contact localization / searchFxy / search trajectory / contact-side是
S4Insertion engaged初始插入深度 / 接触稳定是
S5Insertion depth increasing深度增长 / 轴向力是
S6Fully seated到位深度 / 位姿 / 力学条件终态

Phase 是 categorical state，不承担“70%完成度”这种数值语义。同一 episode 可以多次进入 S2/S3/S4。

2.4 Track B：Physical Progress —— 明确的非单调标签函数

工程定义工业 Progress 定义为“当前物理状态相对于成功目标的 potential”，而不是“历史做到了第几阶段”。首版建议用可测量物理量构造 deterministic label，再用真实 outcome 做校准。所有量必须先归一化到 [0,1]。

Raw physical observables x_t
- d_tip        : end-effector / peg-tip 到目标区域距离
- e_xy         : 横向对准误差
- e_rot        : 轴线角度误差
- d_insert     : 当前插入深度
- q_contact    : 接触质量（居中、稳定、可继续推进）
- p_jam        : jam 指示 / 概率
- p_slip       : slip 指示 / 概率
- p_overload   : 超力风险

Normalized sub-scores (examples)
g_approach = exp(-(d_tip / σ_d)^2)
g_align    = exp(-(e_xy / σ_xy)^2) · exp(-(e_rot / σ_r)^2)
g_depth    = clip(d_insert / d_goal, 0, 1)
g_contact  = clip(q_contact, 0, 1)

Initial physical potential
P_raw(t) = clip(
    w_a·g_approach
  + w_b·g_align
  + w_c·g_depth
  + w_d·g_contact
  - w_j·p_jam
  - w_s·p_slip
  - w_o·p_overload,
  0, 1)

Terminal overrides
if fully_seated: P(t) = 1.0
if hard_abort / part_damage: P(t) = 0.0 or ignore-after-damage

Temporal processing
- normal frames: short EMA / median filter to suppress sensor jitter
- jam / overload onset: penalty applied immediately，不做长窗口平滑
- recovery: P 可下降后重新上升，禁止 cumulative-max 强制单调
参数原则：w_*、σ_* 不是固定真理。阶段0用 20–30 条成功/失败/recovery 试点轨迹做归一化和敏感性分析；参数写入 task config 并版本化。后续可训练一个 calibrated progress model 替代人工 potential，但 deterministic physical progress 必须长期保留为可解释 baseline。

2.5 Contact State 与 Mistake Label

Recoverable mistake 的区间从 physical failure onset 开始，到重新进入稳定有效 insertion/search 状态结束；terminal failure 则直到 reset 或 episode 终止。Human intervention 的 lead/ignore window 不复制论文常数，而应由自有数据估计：

reaction_delay = t_intervention - t_physical_failure_onset

04动作表示、候选生成与 AOP 数据

4.1 Canonical Action Representation

AOP 不直接混用 ACT / π0 / DP / rule controller 的原生动作。统一到 EE-centric 物理语义：

a_canonical = [Δx, Δy, Δz,
               Δrx, Δry, Δrz,
               gripper_state,
               Δt]

optional:
target_force / impedance_gain / primitive_id

所有 candidate action resample 到统一时间基准；若 chunk 长度不同，显式保存 mask / duration，避免模型把 chunk 长度本身当作 policy identity。

4.2 Candidate Action Generator

Candidate 0 : VLA nominal action
Candidate 1 : geometry-based correction
Candidate 2 : contact-side correction
Candidate 3 : withdraw / retry primitive
Candidate 4+: small local perturbations around nominal action

第一版不依赖对 VLA 做大量随机重复采样。Candidate Generator 的目标是扩大“合理局部动作集合”，AOP 的目标是评价，不把动作生成与动作评价混成一个问题。

4.3 Candidate Safety Envelope（AOP 前置）

工程新增任何候选在进入 AOP 之前先经过 deterministic safety filter：

joint / workspace limits
collision-free check
max Cartesian step / rotation step
force-aware forbidden direction
known fixture constraints
hard jam / overload state restrictions

unsafe candidate → reject before AOP

AOP 不能成为“安全过滤器的唯一来源”，否则 OOD 时的错误排序可能直接转化为硬件风险。

4.4 Paired Action 数据：证据等级

来源角色可否称 Ground Truth
Simulation counterfactualpretraining / candidate proposal / coverage expansion否，synthetic supervision
Real recovery高置信度 calibration / finetune局部真实结果
Real matched rollout最终 ranking / product evaluation是，产品结论依据
Selective active probing测量 sim-to-real gap 的少量高价值状态是，但稀疏且高成本
重要限定：真实机器人无法在完全相同微观接触状态上同时执行两个动作。所谓 real paired action 应理解为可重复 reset + matched initial condition 的近似反事实实验。记录 reset 误差、工件磨损、force zeroing、执行顺序，并随机化 AB/BA 顺序以降低漂移。

05分阶段研发路线与 Gate

阶段 0 · 任务、数据、标签与安全定义

0.5–1 周
  • 首个科学验证平台固定为标准 Peg-in-Hole；第二阶段迁移试管/圆柱插入；USB / 光模块 / 标准连接器用于后续商业价值验证。
  • 定义 Paper Track 与 Industrial Track 的 label schema，完成 Task Phase / Progress / Contact / Mistake 字段与版本管理。
  • 确定 Physical Progress 的物理量、归一化范围、初始权重与 terminal override。
  • 盘点 expert / policy success / policy failure / recovery / intervention 数据。
  • 建立 episode/session/OOD split。
  • 产出独立真机安全协议并实测。
Gate 0：若 insertion depth、相对位姿或接触状态无法被可靠测量/估计，则 Industrial Progress 先不要训练模型，优先补测量链路。

阶段 1 · 双轨 Label Engine + Shortcut Baselines

2–2.5 周
  • Paper Track：实现论文 stage-aware success-then-decay 及 label-shape ablations；V_mc 复现使用 soft-target BCE。
  • Industrial Track：实现非单调 Physical Progress、Contact State、Mistake interval 与 provenance。
  • 用 20–30 episodes 做 label timing / 参数敏感性 / 人工复核试点。
  • 训练 Time-only / State-only / DINO+MLP / GRU cheap baselines。
  • MSE / Huber 作为工程 loss ablation，可选，不再承担“确认论文配置”的职责。
Gate 1：若 Physical Progress 无法在 clean success / retry / jam / recovery / terminal failure 上产生符合物理直觉的曲线，停止扩模型，先修 Label Engine。

阶段 2 · ValueFormer State Critic 复现

1 周
  • 冻结 DINOv3 backbone，支持离线 feature cache。
  • 论文风格 2-layer causal Transformer，并保留 GRU 对照。
  • Paper Track 严格使用 BCE 双头训练设置。
  • Industrial Track 单独训练 progress / mistake critic，不混淆两套评价结论。
  • 输出仍定义为 V(s)，不称 AOP。

阶段 3A · 单一固定 Policy 在线验证

1 周
  • ACT / π0 / DP 三选一作为唯一首轮 rollout policy。
  • 检测 clean success / retry / stuck / early collapse / jam-recovery signature。
  • 评估 AP/AUROC、Failure Recall、False Alarms/min、Lead Time、Calibration、Progress correlation。
  • 与 Time-only / State-only / DINO+MLP / GRU baseline 对照。
Gate 2：State Critic 必须在关键 failure metric 上明显超过 shortcut baseline，且不是仅靠时间或关节状态获得高分；否则不进入 AOP。

阶段 3B · Cross-policy Generalization

0.5–1 周
  • 冻结 Stage 3A Critic，不用新 policy 数据重训，直接评估第二种 policy。
  • 检查视觉轨迹、速度分布、动作风格变化是否导致 failure detector 退化。
  • 若需要适配，先比较 normalization / calibration / 少量 finetune，再决定是否需要 policy-conditioned critic。
Gate 3（建议初始口径）：Cross-policy AP/AUROC 相对 ID policy 的下降若超过约 10%，或 Failure Recall 下降超过 10 个百分点，应暂停 AOP 多策略混训并先排查 policy identity shortcut。阈值可在 pilot 后预注册调整。

阶段 4 · Action-conditioned Critic：AOP V0

2–3 周
  • 建立 Canonical Action Representation 和 Candidate Action Generator。
  • Candidate 先过 deterministic safety envelope。
  • 训练固定 horizon Q_H(s,a) multi-head outcomes。
  • Simulation counterfactual pretrain → Real recovery calibration → Real matched paired ranking。
  • 主指标：pairwise action ranking accuracy + 95% CI；辅助指标：ΔProgress、Jam/Slip、ΔPose/ΔDepth。
Gate 4：真实 paired ranking 必须稳定高于随机 0.5；建议把“95% CI 下界高于 0.5”作为最小统计 Gate，并同时检查排序增益是否能转化为真实 success / recovery improvement。否则不进入 Lite-LDA。

阶段 5 · Contact AOP

1–2 周
  • 输入加入 force history / tactile history / contact state。
  • 输出扩展：progress、success_H、jam、slip、contact-side、P(recoverable within H_r)。
  • 按 Vision → +Geometry → +Force → +Tactile 做严格增量消融。
  • Fast contact branch 与低频 AOP/World Critic 分离。
Gate 5：Force/Tactile 必须在 jam/slip/OOD/lead-time/recovery 中至少一个关键产品指标产生可重复增益；若只有离线 loss 变好而真机无增益，则不进入第一版产品主路径。

阶段 6 · Lite-LDA / Future Outcome + Physical Grounding

2 周+
  • 仅在真实 AOP paired ranking 成立后引入 future wrist latent / z_future。
  • 主预测：(z_t, a_chunk) → z_future + contact_future + progress_future。
  • 增加 physical grounding heads：z_t→physical_state_t、z_future→physical_state_future、(z_t,z_future)→Δphysical_state。
  • 优先 grounding：ΔEE-target pose / Δinsertion depth / Δcontact position / Δforce / contact transition。
  • future latent 只有在真实 action ranking / OOD / recovery 上提供额外增益才保留。
Gate 6：若 future latent 仅降低 latent prediction loss，却不改善真实 AOP / OOD / recovery，则停止扩大 World Model。

07真机安全、部署与运行时约束

7.1 真机实验安全协议

  • 轴向/径向力与力矩上限按工件刚度、夹具和末端工具标定。
  • 卡滞退出：连续 N 个控制周期插入深度不增长且力超过阈值，触发保护回撤。
  • 软件保护 + 硬件急停 / 控制器阈值双重冗余。
  • 失败后检查工件和夹具，损坏件不进入下一轮数据。
  • AOP candidate safety filter 在模型排序前执行；模型输出不能绕过安全控制器。

7.2 Serving 优化原则

  • 冻结视觉 backbone 时优先缓存离线特征用于训练；在线 serving 再评估共享 backbone 或 batched multi-view encoder。
  • Critic 与 policy 共享 GPU 时必须测量 policy deadline 受影响程度，而不是只报告 critic latency。
  • 低频 State Critic / AOP 与高频 Contact / Force Residual 分进程或分线程，采用明确 timestamp / stale-action 检查。
  • 记录 observation time、candidate generation time、AOP score time、execution time，避免 action chunk 过期。

V3.2 最终研发原则

  1. 论文复现与工业创新双轨管理：Paper Track 忠实，Industrial Track 可证伪，不互相冒充结论。
  2. Phase 不等于 Progress：工业 Progress 必须由物理状态定义，允许下降和恢复。
  3. 先 V(s)，再 Q_H(s,a)：先证明“当前好不好”，再证明“哪个动作更好”。
  4. Simulation 扩覆盖，Real rollout 定成败：仿真不是毫米级接触的现实 Ground Truth。
  5. Candidate 先过硬安全，再交给 AOP 排序：学习评价器不能替代确定性安全链路。
  6. 触觉必须证明增量价值：不能因为有传感器就默认进入主模型。
  7. World Model 最后做：只有 AOP 已经在真机动作排序上成立，future latent 才有资格进入下一阶段。
  8. 所有结论可追溯：论文配置写版本/章节/公式；工程标签写 config/version/provenance；真机结果写 matched condition 与统计方法。
